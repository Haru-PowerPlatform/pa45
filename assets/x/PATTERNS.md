# X技術Tips レイアウト型カタログ

同じ骨組みが続くと「テンプレの色替え」に見えて飽きられる。
かといって毎回ゼロから考えると品質がぶれる。そこで **固定するもの** と **回すもの** を分けておく。

ネタが決まったら、まず下の「どれを選ぶか」で型を決めてから作り始める。

---

## 固定するもの（ブランド軸・毎回同じ）

これは変えない。シリーズだと一目で分かるための記号。

| 要素 | 中身 |
|---|---|
| タイトルバー | 青グラデ90px／`Vol.NN-1` の白ピル／PAロゴ／タイトル27px（後半を `#FFE08A` でハイライト）／右にマスコット（下にはみ出す） |
| 結論バー（concl） | タイトル直下。青枠＋電球チップ＋19px太字で「この回の要点1文」 |
| 注意帯 or 次回誘導 | 1枚目＝「作り方は2枚目へ」の青バー／2枚目＝「⚠ 使う前に確認」のオレンジ帯 |
| 出典 | 左下に小さく「出典：Microsoft Learn」。実機確認したものはその旨も |
| 人名 | 架空（山田太郎・佐藤花子・鈴木一郎…）。実名は使わない |

## 回すもの（レイアウト型・ネタに合わせて選ぶ）

### A. Before / After 2パネル
**いつ使う**：困りごとが「直る」ネタ。ズレ・手戻り・地獄からの解放。
**骨格**：左パネル（✕・赤系）｜中央エンジンカード＋矢印｜右パネル（✓・緑系）
**必須**：左右の見出しを**25px以上**で対にする（例「そのまま書いた場合／変換を挟んだ場合」）。左右で同じ実画面モックを並べ、**変わったのは1か所だけ**にする（時刻・色・行）。
**過去例**：Vol.65 休み明け受信トレイ、Vol.73 Excel集計、**Vol.74 日付の式**

### B. 流れ3列（①②③）
**いつ使う**：3ステップで説明が終わるネタ。「〜すると→〜が起きて→〜になる」
**骨格**：3列カード。各列の頭に丸番号、上に情景SVG、下に実画面モック
**必須**：見出しは動詞で具体的に（「①打つ」ではなく「①合言葉を入力する」）。各列に「何が起きているか」の補足キャプション。
**過去例**：Vol.63 熱中症アラート、Vol.66 QR備品、Vol.67 資料の鮮度

### C. 主役モック どーん
**いつ使う**：出てくる成果物そのものが驚きになるネタ（PDF・カード・自動生成物）
**骨格**：生成物を画面の6割で大きく1つ。周りに小さく作り方の要点
**必須**：生成物は「本物にしか見えない」精度で。周辺の説明は短く。
**過去例**：Vol.61 書類PDF、Vol.42 アダプティブカード

### D. 会話スレッド型
**いつ使う**：人のやり取りの中で仕組みが動くネタ。Teams・チャット・DM
**骨格**：左にTeams会話（2〜3人）｜中央エンジン｜右に台帳やカード
**必須**：会話は**2〜3人**で自然に。ボットの発言と人の発言を見分けられるように。
**過去例**：Vol.45 スタンプでナレッジ収集（お手本）、Vol.57 報連相カード

### E. 早見表・比較表
**いつ使う**：チートシート、境界線、対応表。**保存される型**。
**骨格**：左に実画面モック1つ（どこに貼るか）｜右に一覧（2列×6行くらい）
**必須**：表だけにしない。**必ず実画面モックを1つ**置いて「どこで使うか」を示す。重要な行は色を変える。
**過去例**：Vol.46 無料とプレミアムの境界、Vol.54/55 Copilot、**Vol.74-2 日付の式12個**

### F. 紙芝居4コマ
**いつ使う**：時間の流れやストーリーが必要なネタ。仕込み→放置→発火→結果
**骨格**：4コマを横または2×2で
**必須**：コマごとに時刻や日付を入れて「時間が経った」ことを見せる。
**過去例**：まだ無い（次に試す枠）

## 文字サイズの下限（2026-07-22 指摘を反映）

**見せ場は大きく。余白は文字で埋める。**「空いたから余白のまま」は不可。

| 場所 | 下限 |
|---|---|
| 左右パネルの見出し（対比の要） | **25px** |
| 結論バー | 19px |
| 中央の大きい一言 | 27px |
| 手順・エンジンカードの行 | 18.5px |
| 実画面モックの本文 | 16px |
| モックの見出し・ラベル | 15.5px |
| 注意帯・補足 | 14.5px |

要素が入り切らない場合は、**文字を小さくするのではなく**、飾り（時計・アイコン）のサイズを落とすか、モックの行数を減らす。

## 作る前のチェック

1. 型はどれか（A〜F）。前回・前々回と同じ型になっていないか
2. 一目で情景が浮かぶ絵があるか（モックとテキストだけになっていないか）
3. 見せ場の文字が25px以上あるか
4. 空白が残っていないか
5. 実測で見切れゼロか（`measure.html` で `scrollHeight-clientHeight` を全要素チェック。マスコットの意図的なはみ出しだけが残る状態が正解）
