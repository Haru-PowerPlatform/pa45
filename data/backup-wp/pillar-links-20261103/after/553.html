変数の初期化の基本

変数の初期化そのものの説明は 変数の初期化（Initialize variable）の使い方 にまとめています。この記事は、空欄チェックに使う応用例です。

Power Automate の変数は、使う前に「変数を初期化する」アクションで用意しておく必要があります。
この記事では、Excel の金額欄が空欄の行を見つけて Teams に知らせるフローを作りながら、初期化の役割と「変数の設定」との違いを整理します。

この記事で分かること

  • 変数を初期化しておく理由
  • 「変数を初期化する」と「変数の設定」の違い
  • 空欄の判定に使う empty() の書き方
  • 判定の結果を変数に入れて、Teams に送る流れ

変数を初期化しておく理由

変数は、フローの途中で値を一時的に入れておく入れ物です。
Power Automate では、入れ物の名前と型を先に決めておかないと、あとのアクションで値を入れられません。
名前・型・最初の値を決めるのが「変数を初期化する」アクションです。

最初の値を空文字にしておくと、どの行を処理したあとでも変数の中身が決まった状態になります。
Power Automate では null（値がない状態）と空文字（長さ0の文字列）が別物として扱われます。
最初の値を決めておけば、条件分岐で null の場合を考えずに済みます。

初期化と値の設定の違い

アクションやること置ける場所回数
変数を初期化する名前・型・最初の値を決めるフローの一番外側だけ。ループや条件の中には置けない1つの変数につき1回
変数の設定用意した変数の値を入れ替えるループや条件の中にも置ける何度でも

今回作るフロー

Excel の表を1行ずつ確認し、金額が空欄なら警告、入力済みなら確認済みのメッセージを Teams に送ります。

  1. フローを手動でトリガーする
  2. 表内に存在する行を一覧表示（Excel の行を取得）
  3. 変数を初期化する（varMessage を用意）
  4. Apply to each（1行ずつ処理）
  5. 条件（金額が空欄か）
  6. 変数の設定（送る文面を入れる）
  7. チャットまたはチャネルでメッセージを投稿する（Teams に送る）

使うコネクタは Excel Online (Business) と Microsoft Teams で、どちらも標準コネクタです。
プレミアムのライセンスは要りません。

サンプルの Excel

OneDrive か SharePoint に置いた Excel に、次の表を作ります。
「表内に存在する行を一覧表示」はテーブルしか読めないので、範囲を選んで「テーブルとして書式設定」をしておきます。

名前金額
佐藤12000
鈴木（空欄）
高橋5000

作り方

1フローを作る

「インスタント クラウド フロー」を選び、トリガーに「フローを手動でトリガーする」を選びます。
試しているあいだは、好きなときにボタンで動かせるトリガーにしておくと確認が早くなります。

2Excel の行を取得する

「Excel Online (Business)」の「表内に存在する行を一覧表示」を追加します。
場所・ドキュメント ライブラリ・ファイル・テーブルの順に、サンプルの Excel を指定します。

3変数を初期化する

「変数を初期化する」を追加し、名前を varMessage、種類を文字列にします。
値は空のままにします。
このアクションはループの中に置けないので、次の Apply to each より前に置きます。

41行ずつ処理する

「Apply to each」を追加し、「表内に存在する行を一覧表示」の動的コンテンツ value を渡します。
ここから先のアクションは、すべてこのループの中に置きます。
新しいデザイナーではループの名前が「For each」と表示されることがあります。
そのときは、次の式の Apply_to_each を For_each に置き換えます。

5金額が空欄かを判定する

ループの中に「条件」を追加し、左の欄に次の式を入れます。
中央は「次の値に等しい」、右の欄は式で true と入れます。

empty(items('Apply_to_each')?['金額'])

empty() は、値が空文字でも null でも true を返します。
Excel の空欄がどちらで届いても、同じ式で判定できます。

6送る文面を変数に入れる

条件の「はい」と「いいえ」に、それぞれ「変数の設定」を追加します。
名前は varMessage を選び、値に次の文面を入れます。

はい（空欄）の場合

【未入力】金額が空欄です。値を入力してください。
名前：@{items('Apply_to_each')?['名前']}

いいえ（入力済み）の場合

【入力済み】
名前：@{items('Apply_to_each')?['名前']}
金額：@{items('Apply_to_each')?['金額']}
7Teams に送る

条件のあと（ループの中）に、「Microsoft Teams」の「チャットまたはチャネルでメッセージを投稿する」を追加します。
投稿者はフローボット、投稿先はフローボットとのチャットにして、Recipient に自分のメールアドレスを入れます。
メッセージには動的コンテンツの varMessage を入れます。

動かしてみる

保存して「テスト」から手動で実行します。
サンプルの3行なら Teams に3通届き、鈴木さんの行だけが【未入力】の文面になります。
実行履歴を開くと、行ごとに条件がどちらに進んだかを確認できます。

確認ポイント

  • 「変数を初期化する」はループや条件の中に置けません。
    変数が必要になったら、フローの一番外側に足します。
  • 種類を整数にした変数に文字列を入れると、「変数の設定」が失敗します。
    入れる値と変数の種類をそろえます。
  • 金額が 0 の行は空欄ではないので、empty() では拾いません。
    0 も未入力として扱いたい場合は、条件を別に足します。
  • この形だと、行の数だけ Teams に通知が届きます。
    まとめて1通にしたい場合は、配列の変数に溜めて最後に1回送る形にします。
    配列の扱いは 配列のフィルター処理のまとめで整理しています。

まとめ

この記事のまとめ

  • 変数は「変数を初期化する」で名前・型・最初の値を決めてから使う
  • 初期化はフローの一番外側で1回、「変数の設定」はループの中でも何度でも
  • 空欄の判定は empty()。空文字と null の両方を拾う
  • 行ごとの判定結果を変数に入れておくと、通知の文面を1つのアクションで送れる
