PA45｜第27回 ／ 頼み方1

材料を先に見せてから頼む

Tip 1
1
いきなり「作って」と言うと、Copilot は項目名を推測します。テスト実行の出力を先に貼ると、実物の名前で答えます。
Power Automate のフローを作っています。 いまテスト実行したら、次の出力が返ってきました。 （ここにテスト実行の出力をそのまま貼る） この中から 「○○」 と 「△△」 を取り出して、次のアクションで使いたいです。 動的コンテンツの選び方か、式のどちらかで教えてください。
いちばん効きます。 項目の名前は環境ごとに違うので、見せないかぎり当てられません。

PA45｜第27回 ／ 頼み方2

「日本語のアクション名も書いて」と頼む

Tip 2
2
そのまま聞くと Create HTML table のように英語名だけで返ってきます。日本語の画面にその名前は無いので、そこで手が止まります。
Power Automate で （やりたいこと） を作りたいです。 私の画面は日本語表示です。 アクション名は「英語名（日本語名）」の形で、両方書いてください。 設定する項目の名前も、日本語画面での表示名で書いてください。 初心者なので、順番に、何をどこに入れるかまで教えてください。
それでも英語のまま返ることがあります。 そのときは 「日本語名も」ともう一度頼む。一発で決まらないのは普通です。

PA45｜第27回 ／ 頼み方3

形を指定する ―「式だけちょうだい」

Tip 3
3
放っておくと長い解説が返ってきます。欲しい形を先に伝えると、必要な一行だけが返ります。
Power Automate の式だけを教えてください。説明は要りません。 やりたいこと：（例）UTCで届いた日時を、日本時間の「2026/09/10 20:15」の形にしたい 使う場所：（例）メール本文の差し込み 式だけを1行で返してください。
「3行で」「表にして」も同じ効き方をします。 欲しい形を先に言うのがコツです。

PA45｜第27回 ／ 頼み方4

エラー文は、訳さずそのまま貼る

Tip 4
4
初心者がいちばん止まるのがエラーです。英語のまま貼って構いません。意味だけでなく、直す場所まで返ってきます。
Power Automate でフローを実行したら、次のエラーが出ました。 （エラーメッセージをそのまま貼る。訳さなくてよい） ・何が起きているのか ・どのアクションの、どの設定を直せばよいのか この2つを、初心者にも分かる言葉で教えてください。
自分で英語を訳してから聞かないこと。 訳すと情報が落ちて、かえって遠回りになります。

PA45｜第27回 ／ 頼み方5

フローの中身を読ませて、説明させる

Tip 5
5
人から引き継いだフロー、昔つくった自分のフロー。開いても分からないとき、中身をそのまま読ませると早いです。
これは Power Automate のフローの中身です。 （フローのJSONを貼る） ・このフローが何をしているのか ・つまずきそうな所はどこか この2つを、Power Automate を触ったことがない人にも分かる言葉で説明してください。
引き継ぎのときに効きます。 作った人がいなくなったフローを、読める形に翻訳してもらう使い方です。

PA45｜第27回 ／ 検品

★ 実在しない関数を返してくることがあります

検品
今日の質問で、Copilot は「今週分だけ取る」式としてこれを返してきました。
Created ge '@{formatDateTime(startOfWeek(utcNow()),'yyyy-MM-ddTHH:mm:ssZ')}'

実在する

startOfDay
startOfHour
startOfMonth

実在しない

startOfWeek
Microsoft Learn の関数一覧に無い

だから「小さく試す」。 式はコピーしたらそのアクションだけテスト実行して、通ることを確かめてから先へ進みます。

PA45｜第27回 ／ 注意

貼る前に、必ずやること

Rules

🔒 機密は置き換える

会社名・氏名・メールアドレス・取引先名・金額はサンプルの値にしてから貼る

🔍 そのまま信じない

引用元として示されたページが、中身と関係ないことがあります

⬜ 空欄を疑う

必須の欄が空のまま返ることがあります。空欄は、AI が人に渡した場所

うまくいかないときは、会話を続ける。 「その表に余計な列が出ます」「もっと短く」——一発で決まらないのが普通です。
