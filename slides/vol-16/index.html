こんな困りごと、ありませんか？ ── 式・JSON あるある

Why

「式の書き方を忘れた」「このカッコの中、何を書くんだっけ…」。検索してもピンと来ず、手が止まる。──その 調べる時間、AIに丸ごと肩代わりしてもらえます。

式が思い出せない

convertTimeZone の引数の順番、毎回ググっている。

JSONが読めない

実行履歴の body/... が暗号にしか見えない。

だからCopilot

材料を貼って聞くだけ。式もJSONの読み方も、その場で答えが返る。今日それを体感します。

🎯 今日のゴール： 「分からない→止まる」を「分からない→AIに聞く→進む」に。45分で AIとの付き合い方を持って帰りましょう。

★ STEP1 ／ 材料を用意する

まず動かして「出力」を出す ── Copilotに渡す材料づくり

Get the material

🎯 このSTEPの目的

Copilotに渡す "本物の材料" を手に入れる。式やJSONの相談は、実際のデータがあるほど答えが正確になります。

やること

  • トリガー「Formsに回答が送信されたとき」を置く
  • テスト用にフォームへ 1回だけ回答
  • 実行履歴を開き、トリガーの 「出力」をコピー
▼ トリガーの出力（コピーするのはコレ）
{ "responder": "yamada@example.com", "submitDate": "2026-06-25T11:30:00Z", "answers": { … 回答内容 … } }
⚠️ ここではまだCopilotに聞きません。 先に "材料" を用意しておくのが、答えの精度を上げる第一歩。次のSTEPでこのJSONを使います。

★ STEP2 ／ 今日の肝

出力JSONを "先に" Copilotへ ── これが精度の決め手

Priming

🎯 目的：「今このデータを扱う」とCopilotに 先に教える（プライミング）。文脈を持たせてから頼むと、項目名まで正しく当ててくれます。

🙂
あなた
これからPower Automateのフローを作ります。まず トリガーの出力JSON を共有します。今は読むだけでOK、項目名を覚えておいて。次の質問で使います👇
{ "responder": "...", "submitDate": "2026-06-25T11:30:00Z", "answers": {…} }
🤖
Copilot
了解しました。responder（回答者）と submitDate（送信日時・UTC）を確認しました。次のご質問どうぞ。
✕ 先に渡さないと「たぶん body/date かな？」と当て推量で 項目名を外す／やり直しが増える
→
✓ 先に渡すと実際の submitDate を使って 一発で正確／この後の式・エラー直しもブレない
同じ質問でも、"先に材料" があるだけで答えの精度が変わります。 今日いちばんの手土産はこれ。「いきなり頼まない、まず見せる」。

★ STEP3 ／ 式を書かせる

式を書かせる ── convertTimeZone をことばで

Let AI write it

🎯 このSTEPの目的

送信日時(UTC)を 日本語の日付に直す式を、引数の順番を覚えていなくても ことばで頼んでもらう。

話しかけ方のコツ

  • どの項目か（さっきの submitDate）
  • どうしたいか（日本時間の日付に）
  • 形を指定（式だけ／2026年6月25日（木））
🙂
あなた
さっき共有したJSONの submitDate を、日本時間の「2026年6月25日（木）」の形にしたい。Power Automateの 式だけ教えて。
🤖
Copilot
文脈を踏まえて👇
convertTimeZone(triggerOutputs()?['body/submitDate'],'UTC','Tokyo Standard Time','yyyy年M月d日(ddd)')
STEP2の効果がここで出る。 先にJSONを渡したから、項目名（submitDate）まで合わせた式が返ってくる。あとは貼って実行するだけ。

★ STEP4 ／ エラーを直す

わざとエラーを出して直す ── 赤い文字をそのまま貼る

Debug with AI

🎯 このSTEPの目的

エラーは怖くない、と体で覚える。項目名をわざとズラして（submitDate→SubmitDate）赤エラーを出し、そのまま貼って直してもらう。

話しかけ方のコツ

  • エラー文を 消さずに全文 貼る
  • 「原因と直し方を教えて」と一言添える
🙂
あなた
この式でエラーが出ました。原因と直し方を教えて👇
InvalidTemplate: ... 'body/SubmitDate' cannot be evaluated
🤖
Copilot
項目名の 大文字・小文字ズレです。実際は submitDate。直すと解決します👇
...triggerOutputs()?['body/submitDate']...
ポイント： エラー文は最高のヒント。文脈を持つCopilot（STEP2）なら、どの項目がおかしいかまで一発で当ててくれます。

★ STEP5 ／ JSONを読ませる

完成フローのJSONを読ませる ── 「何してる？」を説明させる

Understand

🎯 このSTEPの目的

完成したフロー全体のJSONを貼り、「各アクションが何をしているか」を説明させる。自分の理解にも 引き継ぎメモにもなります。

JSONの使い道は2回。
① 入力＝精度UP（STEP2）
② 読解＝理解（このSTEP）
🙂
あなた
この完成フローのJSONです。各アクションが何をしているか、初心者向けに3行で説明して👇（JSONを貼る）
🤖
Copilot
①Formsの回答を受け取り
②送信日時を日本時間の日付に整形し
③その日付を本文にしてメール送信、しています。
つながり： Vol.14「JSONの読み方」→ 今日は 読み方ごとCopilotに任せる。難しいJSONも「で、これ何してるの？」と聞けば言語化してくれます。

★ まとめ ／ PROMPT

うまく頼む3つのコツ ── これだけ覚えて帰る

Prompt tips
1

材料を "先に" 渡す

いきなり頼まず、JSONやデータをまず共有して「これを扱う」と教える（プライミング）。今日の核。

2

出力形式を指定する

「式だけ」「3行で」「日本語の日付で」など、欲しい形を先に言う。やり直しが減る。

3

役割を与える

「Power Automate初心者向けに」と一言。専門用語を噛み砕いて答えてくれる。

おすすめテンプレ：「Power Automate初心者です。まず材料を共有します〔JSONを貼る〕。これを扱って〔やりたいこと〕。式だけ教えて。」── この型に当てはめるだけ。

PA45｜第16回 ／ 大切なこと

使うときの注意 ── ここだけは守ろう

Cautions
🔒

機密データを貼らない

個人情報・社外秘・実在のメアドはチャットに入れない。サンプル値に置き換えてから相談。

✅

生成物は必ず検証

AIの式も 間違うことがある。そのまま信じず、実行して確かめてから本番へ。

🏢

会社の設定を確認

テナントによっては Copilotがオフのことも。使えない時は管理者に相談を。

合言葉： AIは すごく頼れる下書き役。でも 最後に確かめるのは自分。この2つを守れば、安心して毎日の味方にできます。
