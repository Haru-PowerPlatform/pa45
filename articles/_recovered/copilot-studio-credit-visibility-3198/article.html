Copilot Studio は使った分だけクレジットを消費します。 では、その実績を管理側のどこで見るのか。 Power Platform 管理センターの Copilot のページを実機で確認しました。 合計は見えましたが、エージェント別の内訳は既定では出ませんでした。
この記事は企業導入編の4本目です。 ①：開発用の環境を分ける／②：DLPで「認証なし」を止める／③：マネージド環境で共有範囲を絞る

①〜③で、作る場所・公開の仕方・配る範囲を決めました。 ここまではやらせないための設定です。

運用に入ると、次に聞かれるのは「実際どれだけ使っているのか」です。 使うほど課金される仕組みである以上、消費を見る場所を先に押さえておきます。

① 消費はどこで見るか

この節ですること
管理センターのどこにクレジットの消費が出るのかを開きます。
終わるとこうなる
毎月どこを見ればよいかが決まります。

1Copilot のページを開く

  1. 管理センター（admin.powerplatform.microsoft.com）を開く
  2. 左端のアイコン列から「Copilot」を選ぶ（セキュリティの1つ下）
  3. パネルの「Copilot Studio」をクリック
なぜそうするか環境やDLPは「管理」「セキュリティ」の配下にあるが、消費と機能のオンオフは「Copilot」の配下にある。 探す場所が別なので、最初に位置を覚えておく。
 
消費は Copilot → Copilot Studio の画面で見られます。 毎月どこを開けばいいか、場所だけ先に決めておくとラクでした。

② 合計と傾向を読む

この節ですること
表示された数字とグラフの読み方を確認します。
終わるとこうなる
いつ何にクレジットを使ったのかが分かります。
用語Copilot クレジット：Copilot Studio の利用量をはかる単位。 会話や実行のたびに消費されます。
用語前払いと従量課金：先に買っておく枠と、使った分だけ後から請求される形。 画面では別々の数字で表示されます。
画面に出ていたのは次の項目です。
  • 請求済みのメッセージ／アクティブなエージェント／エージェント セッションの成功率
  • 使用済みの前払い Copilot クレジットと従量課金制 Copilot クレジットの2本立て
  • 日ごとの消費量を示す棒グラフ
検証に使っているテナントでは、前払いクレジットの消費が 11、従量課金制が 0 でした。 グラフを見ると、消費は8月1日に集中しています。 この日はエージェント同士の取り次ぎと、評価（Evaluate）機能を試した日でした。
会話を試した分が、日付つきで管理画面に残っていました。 「いつ・どれだけ使ったか」は、作った本人が申告しなくても管理側で見えます。 前払いと従量課金が別々に出るので、上限を超えて課金に入ったかどうかもここで分かります。 ただし反映には時間差があります。 後述のとおり、当日の操作がその日のうちにグラフへ出ないことがありました。

※ この画面に出ないものがある

ページ上部に「このページには、Microsoft 365 Copilot の Copilot Studio のライト エクスペリエンスで作成されたエージェントに関するデータは含まれていません」と書かれています。 Microsoft 365 Copilot 側で作られたエージェントは、この集計の外です。 全体像を把握するには、別の管理画面も見る必要があります。

③ 内訳が出ない理由

この節ですること
エージェント別の内訳が出ない理由と、出すための設定を見ます。
終わるとこうなる
内訳が空でも、設定漏れだと判断できるようになります。
合計が分かっても、運用で知りたいのはどのエージェントが使っているかです。 ページを下にスクロールすると、その一覧がありました。
用語テナント全体の分析：会社全体の利用状況を集める設定。 有効にすると、どのエージェントがどれだけ使われたかが見えるようになります。
エージェント別の枠には、数字ではなくこう表示されていました。
使用状況データを表示するには、設定を更新してください
同じ画面の上には、管理者向けの推奨事項が並んでいます。 1件目が「テナント全体の分析を有効にして、マネージド プラットフォーム全体のエクスペリエンスを向上させます」で、重大度は高でした。
既定では内訳が見えない使った合計は最初から見えますが、どのエージェントが使ったかは既定では見えません。 テナント全体の分析を有効にして、はじめて一覧が出ます。 「使いすぎを検知したい」という要件があるなら、この有効化が前提になります。
なぜそうするか内訳が見えないまま運用すると、合計が増えたときに原因を特定できない。 止めるべき対象が分からないので、結局「全部禁止」の判断になりやすい。 先に見える状態を作っておくほうが、あとで細かく許可できる。
 
エージェント別の内訳は既定だと出なくて、設定を変えないと空のままです。 私は最初、使っていないだけかと思いました。

④ テナント単位の設定はどこか

この節ですること
テナント全体で機能ごとに止められる設定の場所を見ます。
終わるとこうなる
環境単位と全社単位の2段があると分かります。
推奨事項の有効化は、同じ Copilot のパネルにある「設定」から行います。 ここを開くと、Copilot Studio の機能がテナント単位で並んでいました。
  • コンピューター ユース／computer use のアクセスの制御
  • コード生成と実行：エージェントがコードを書いて実行する機能
  • 接続されたエージェント（プレビュー）：エージェントから別のエージェントを呼び出す
  • ホステッド ブラウザー（テナント レベル）：有効にすると、Azure のコンプライアンス境界を超えてデータが Windows 365 に送られることに同意したものと見なされる、と明記
  • エージェントが使用するナレッジ ソース／エージェントのスキル
さらに下には、セキュリティに近い項目が続きます。
用語トランスクリプト：エージェントとの会話の記録。 個人を特定できる情報が含まれることがあるため、誰が見られるかを決める項目があります。
  • クライアント アプリケーションのアクセス制御：データ流出防止をサポート
  • エージェントの認証（プレビュー）：公開されたエージェントへのアクセスを制限する
  • 共有の管理：③で環境単位に設定したものと同じ考え方
  • エージェント アクセス チャネル（プレビュー）：どのチャネルからアクセスできるかを制御
  • 会話からトランスクリプトへのアクセス：会話には機密情報や個人を特定できる情報が含まれる可能性がある、と注記
③でやった「共有の管理」は環境単位でしたが、同じ名前の設定がテナント単位にもあります。 まず1つの環境で試し、方針が固まったらテナント側に上げる、という順番が取れます。 逆に、テナント側でオフにした機能は、環境で許可しても使えません。
切り替えの範囲に注意この画面の設定はテナント全体に効きます。 1つの環境で試す、という逃げ道がないので、検証環境で確かめてから触ります。 今回は内容の確認までにしています。

⑤ 実測：クレジットが0でも実行できることがある

この節ですること
クレジットが残っていない状態で実行して、何が起きるかを見ます。
終わるとこうなる
必ず止まるとは限らないので、動く前提で見積もる判断ができます。
この画面の数字がどう動くかを、日をまたいで確かめました。 結果は一定ではありませんでした。
  • 8月10日：エージェントからフローを実行しようとしたところ、403 InsufficientMcsCredits で止まった
  • 8月21日：別のエージェントで同じ形のフローを実行したところ、最後まで動いて Teams に通知が届いた
  • 同じ日にこの画面を開いても、前払いクレジットの数字は 11 のままで、当日の棒はグラフに立っていなかった
「必ず止まる」わけではないクレジットの枠が無いと実行系は止まる、と一度は確認しました。 しかし別の日には同じ構成が通りました。 猶予期間や枠の扱いが変わると挙動も変わります。 「止まるはず」を前提に設計せず、実際に動いた前提で費用を見積もるほうが安全です。
なぜそうするか管理側の数字はその場で増えないことがある。 操作した直後にグラフを見て「消費していない」と判断すると、翌日に計上されて驚くことになる。 費用を確認するなら、日をまたいで同じ画面を見る。
 
クレジットが残っていなくても動くことがありました。 「必ず止まる」前提だと見誤るので、動く前提で見積もるようにしています。

作業前に押さえておく仕様

  • 消費の実績は Copilot → Copilot Studio：前払いと従量課金が別々に出る
  • 反映には時間差がある：当日の操作がその日のグラフに出ないことがある
  • クレジットが0でも実行できる場合がある：403で止まった日と、通った日の両方を実測した
  • エージェント別の内訳は既定で非表示：テナント全体の分析を有効にする必要がある
  • Microsoft 365 Copilot 側のエージェントは集計外：この画面だけでは全体を把握できない
  • 機能のオンオフは Copilot → 設定：コード実行・ホステッドブラウザー・スキルなどが個別に並ぶ
  • ホステッド ブラウザーはデータの送り先が変わる：有効化＝コンプライアンス境界を超える同意
  • 設定はテナント全体に効く：環境単位のDLPやマネージド環境とは範囲が違う
