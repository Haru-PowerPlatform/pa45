Copilot Studio のエージェントに、右パネルの「Skills」という項目があります。
指示文（Instructions）にもツールにも見えて、最初は違いが分かりませんでした。
実際に1つ作って、指示文の一部を Skill に切り出してみた記録です。
触ってみて、これは「手順を“型”に切り出す」仕組みだと分かってきました。

エージェントに「あれもこれも」と手順を書き足していくと、Instructions（指示文）がどんどん長くなっていきます。
Skills は、その手順を名前をつけた“型”として、指示文の外に出しておくための仕組みです。

① Skills は「4つめの持たせ方」

この節で分かること
Skills が4つめの持たせ方だと確認します。
読み終えるとこうなる
他の3つとの違いが分かります。

エージェントに何かを持たせる方法は、これまで触ってきた中では3つでした。
Skills は、そこに加わる4つめです。

持たせ方中身たとえると
Instructions自由文の指示人柄・全体ルール
Tools外部のアクション道具
Knowledge参照する資料手元の本
Skills構造化した手順手順書・型

Instructions を「常にはたらく性格」だとすると、Skill は「ある場面のときだけ呼び出される、決まったやり方」。
こう並べてみて、ようやく違いが飲み込めました。

 
Skills は、ナレッジ・ツール・フローに続く4つめの持たせ方です。
手順を型に切り出しておくイメージです。

③ Skill は何でできているか

この節で分かること
Skill の構成要素を見ます。
読み終えるとこうなる
何を書けばよいかが分かります。

ファイルを用意しなくても、「Create from blank」から中身を作れました。
開いてみると、Skill は Name／Description／Instructions の3つでできていました。

  • Name：スキルの名前（英数字・64字まで）
  • Description：何をする／いつ使うか。ここで発火が決まります（ツールや取り次ぎと同じ原理）
  • Instructions：手順そのもの。
    決まった型がある

Instructions には、最初からテンプレートが入っていました。
こういう形です。

When this skill is activated: 1. [最初にやること] 2. [次にやること] ## Guidelines - [守ること・制約] ## Examples User request:「[入力例]」 Expected behavior: [どう振る舞うか] ## Notes [補足・例外・知っておくべきこと]
「発動したら①②の順にやる。
守ることはこれ。
例はこれ」——という手順書そのものに、名前をつけて持たせる。
触ってみて、これが Skill だと分かりました。Description が入口（いつ使うか）、Instructions が中身（どうやるか）、という役割分担です。

⑤ 指示文から手順を切り出す（散らからせない）

この節ですること
長い指示文から手順を切り出します。
終わるとこうなる
指示文が散らからずに済みます。

Skill のありがたみが分かってきたのは、長くなった指示文から、手順を切り出したときでした。

今回の案内係は、Instructions に「受講生が申し込みたいと言ったら、メール送信ツールで担当に知らせる。
宛先は…、件名は…」という手順を、長い箇条書きで書いていました。
これを apply-handling という Skill に切り出し、Instructions からはその箇条書きを削除しました。

  • 切り出す前：Instructions に「性格」と「申込対応の手順」が混在して長い
  • 切り出した後：Instructions は「性格・全体ルール」だけになって短い。
    申込対応の手順は Skill に独立
性格は Instructions、個別の手順は Skill。
この2つを分けてみたら、指示文が散らからず、手順も使い回せました。手順が増えるほど、この切り分けが効いてくるはずです。
 
指示文が長くなってきたら、手順を Skill に切り出すと散らかりません。
私は指示文が膨らんだときに整理用として使っています。

まとめ

今回ひととおり触ってみて、分かったことを整理します。

  • Skills は4つめの持たせ方（Instructions／Tools／Knowledge に続く）
  • 中身は SKILL.md：名前・説明を YAML で書く、と画面にあった。
    ファイルで持ち運べる
  • 3要素：Name／Description（いつ使う）／Instructions（手順の型）
  • 使い分け：性格は Instructions、個別の手順は Skill に切り出す

手順を全部 Instructions に書くと、いずれ読みづらくなります。
Skill は、その手順を名前つきの“型”に外へ出して、指示文をすっきり保つための道具でした。
まだ使いはじめたばかりなので、これから使い込む中で気づいたことがあれば、また書き足していきます。

エージェントに持たせる要素（部品）を、困りごとにどう当てるかは 困りごとを“部品”に翻訳する にまとめています。
